Official Technical Specification v1.0

MOS (Modern Viewport Motion Engine)

Lightweight viewport animation trigger, kinetic typography engine, velocity marquee stream, and progressive editorial scroll scrubber. Engineered for hardware-accelerated fluid motion with zero dependencies.

Author: SOUNDARRAJAN-A
License: MIT Open Source
Architecture: Zero Dependencies
Compositing: GPU Accelerated

1. Overview & Architecture

MOS is a fast, zero-dependency browser motion system designed to replace heavy legacy animation libraries. Built from the ground up around the modern IntersectionObserver API and pure CSS GPU compositing pipelines (transform, opacity, filter, clip-path), MOS achieves rock-solid, fluid motion on both desktop and mobile devices.

Unlike legacy libraries that trigger reflows by calculating element bounding boxes on scroll events, MOS uses a decoupled asynchronous lifecycle:

Core Engine Principles
  • Zero Layout Shifts (CLS 0.0): No dimensions, margins, or padding are mutated during animation execution.
  • Two-Way Scroll Lifecycle: Elements animate in on entry and reset cleanly when scrolled out of view, replaying on demand.
  • Anti-Flicker Boundary Hysteresis: An 80px boundary clearance buffer prevents layout chattering when elements near viewport edges.
  • Pure CSS Keyframe Engines: Complex character and word split animations run entirely on browser compositor threads.

4. Velocity Marquee Ticker Engine

The Velocity Marquee provides continuous, hardware-accelerated horizontal text streaming with automatic infinite looping. It supports multi-element typography, glowing separator dots, outline strokes, and automatic single-row duplication.

Standard Marquee Markup

HTML Markup 
<div class="mos-ticker-wrap">
  <div class="mos-ticker-track-left">
    <div class="ticker-row">
      <span class="ticker-item ticker-item-solid">ULTRA LIGHTWEIGHT <span class="ticker-dot"></span></span>
      <span class="ticker-item ticker-item-outline">ZERO DEPENDENCIES <span class="ticker-dot"></span></span>
      <span class="ticker-item ticker-item-accent">FLUID VELOCITY MOTION <span class="ticker-dot"></span></span>
    </div>
    <!-- Duplicate row for seamless infinite looping -->
    <div class="ticker-row" aria-hidden="true">
      <span class="ticker-item ticker-item-solid">ULTRA LIGHTWEIGHT <span class="ticker-dot"></span></span>
      <span class="ticker-item ticker-item-outline">ZERO DEPENDENCIES <span class="ticker-dot"></span></span>
      <span class="ticker-item ticker-item-accent">FLUID VELOCITY MOTION <span class="ticker-dot"></span></span>
    </div>
  </div>
</div>
Automatic Features in MOS Marquee

1. Reverse Direction: Use class="mos-ticker-track-right" for reverse motion.
2. Auto-Duplication: If only one .ticker-row is provided, mos.js automatically duplicates it with aria-hidden="true" to guarantee an infinite loop.
3. Hover Pause: Hovering over the ticker automatically pauses animation smoothly via pure CSS.

7. JavaScript API & Configuration Options

MOS exposes a global window.MOS object with full programmatic controls:

API Methods

Method Parameters Description
MOS.init(options) Configuration Object (Optional) Initializes split-text, marquees, scrubbers, and observers
MOS.refresh() None Re-scans DOM for dynamically inserted elements / single page apps
MOS.updateScrubs() None Recalculates scroll progress on all active editorial scrub paragraphs

Configuration Options

JavaScript 
MOS.init({
  // Trigger once on entry or replay on two-way scroll (default: false)
  once: false,

  // Viewport intersection root margin (default: '0px 0px -40px 0px')
  rootMargin: '0px 0px -40px 0px',

  // Ratio of element visibility required to trigger (default: 0)
  threshold: 0
});

8. Anti-Flicker Architecture & Hysteresis Buffer

Legacy scroll libraries often suffer from Layout Hysteresis: when an element exits the viewport, removing the animation class restores its initial transform (e.g. translateY(30px)), which shifts the element back into the viewport, triggering an infinite rapid chattering flicker.

MOS completely eliminates this issue with a dual-stage safety mechanism:

The MOS Hysteresis Solution
  1. Sticky Retention at Top of Screen: Elements that have entered the screen and scrolled past the top boundary remain rendered. They are never removed while the user is reading downwards.
  2. 80px Clearance Buffer for Reset: Elements are only reset when they have exited more than 80px below the bottom of the viewport (rect.top > windowH + 80). Transform shifts (30-40px) can never bridge this 80px gap, making chattering physically impossible.

10. Frequently Asked Questions (FAQ)

Q: Can I use MOS without any CSS or JS frameworks?

Yes. MOS is 100% vanilla HTML, CSS, and JavaScript. It does not require React, Vue, jQuery, or any build steps.

Q: How do I make animations trigger only once?

Pass once: true to MOS.init({ once: true }). Elements will animate when first scrolled into view and remain permanently visible.

Q: Why did my ticker wrap vertically in an online sandbox?

If your sandbox cached an older version of mos.css, ensure you include mos.js. The latest mos.js automatically enforces inline flex layout and nowrap rules directly on all ticker rows.
